# Rust Idiomatic

**Contracts.** Make ownership and caller expectations visible in ordinary Rust: who owns a value, who may mutate it, what absence and failure mean, and what crosses a task boundary. Derive those expectations from accepted requirements and API contracts, then check the existing representation against them. Honor supplied requirements and preserve settled choices outside the requested change; resolve only what the task leaves open.

Borrow through slices, string slices, and paths when ownership is unnecessary; move values when responsibility transfers, and a function that needs ownership takes it rather than borrowing and cloning. Prefer owned data in structs unless a borrow is worth a lifetime on every container. In application code take concrete types rather than impl Into or impl AsRef; those pay off in widely used libraries. For a borrow conflict, inspect data flow and scope before adding a clone, Arc, or Mutex. Prefer unique ownership: Arc, Rc, and interior mutability are for sharing the design actually needs, and &mut self says more than a hidden lock. Move out of a &mut place with mem::take or mem::replace rather than cloning, and tie cleanup to a value with Drop so it runs on every path, including early return and panic. If a transition only inspects state or updates retained fields, borrow in place; extraction adds a restoration path. For an actual payload transfer, use the [ownership example](references/ownership.md). Identify the invariant before sharing mutation; preserve atomicity and resource bounds. An Arc clone shares an allocation, not synchronized mutation, and a guard across await exposes contention and deadlock.

Choose enums for mutually exclusive alternatives: a status, phase, or flag beside fields valid only in some states becomes one enum carrying those fields, so the compiler rejects what a comment could only ask for. Keep independently varying facts independent; the [representation example](references/representation.md) distinguishes joint presence from a shared phase. Parse at the boundary: turn raw input into a type that proves what was checked and pass that type inward. Give quantities and identifiers that can be swapped in one signature distinct newtypes; a type alias does not separate them. An argument unreadable at the call site, such as a bare bool, becomes an enum or two functions; prefer named fields to tuples outside very local code. A field under an invariant stays private behind a constructor; a field with no invariant needs no getter. Use the std type for the concept, such as Duration or PathBuf. Encoding states in types moves wrong-order errors to compile time but has trade-offs, so weigh it against an enum. Use Option and Result to preserve absence and failure, not sentinels. Before storing derived state, identify the current history, cost, or snapshot requirement that justifies its synchronization. Trace every construction and mutation path of a validated type, including conversions, deserialization, defaults, and exposed fields; a constructor alone does not close them. Raw input may remain unchecked until its existing validation boundary.

Add standard conversion and comparison traits when their semantics fit. Implement the standard trait rather than a custom method with its purpose, From rather than Into, and TryFrom rather than a lossy as cast where a value may not fit; reserve Deref for smart pointers and operators for their mathematical meaning. Derive rather than hand-write an equivalent impl. Every public type is Debug, and types meant to be read are Display; hand-write them only to redact. Application code adds other traits when needed, while a published library implements the common ones eagerly because the orphan rule stops users from adding them. When identity or ordering changes, check agreement among implemented PartialEq, Eq, PartialOrd, Ord, and Hash, especially when mixing derived and manual implementations. For Ord, comparison returns Equal exactly when equality holds, and partial comparison agrees with total comparison; equal values hash equally when Hash exists. Do not add ordering or hashing merely to complete the trait set.

Library crates expose typed errors and preserve causes through a source; the composition root selects exit codes. Keep Display operator-readable and free of secrets. Tokio's spawn requires a Send + 'static future: give the task the data it needs without widening lifetimes. Public types are Send and Sync where possible. For async methods called through dyn, retain a suitable existing adapter, as this service's Probe does; generic-only traits may use async methods.

Use iterators for readable transformations and loops for clearer stateful control flow; collecting changes memory use. A combinator earns its place when it names what happens, such as any; long chains with conditionals or side effects become loops. A queue is a VecDeque; a sorted or range-queried map is a BTreeMap. Preserve ordering and byte versus text distinctions, and decide overflow explicitly where callers control the values. For replacement or iteration effects, use [collections and flow](references/collections-and-flow.md). This workspace forbids unsafe code; a need for it reopens the design rather than the lint. Elsewhere follow the project's safety policy; compilation alone is not a soundness proof.

Names state cost and ownership: as_ is free, to_ is expensive, into_ consumes. Getters omit get_, iterator methods are iter, iter_mut, and into_iter, and error types keep one word order. Avoid abbreviations an outsider would not know.

For review, explain the contract issue and the smallest justified change without editing files. For implementation, finish with formatted code and focused checks for the behavior or type contract affected. Avoid unrelated modernization or abstractions that obscure the operation; neither a clone nor a shared owner is wrong merely by its spelling.
