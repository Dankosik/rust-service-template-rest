# Rust Idiomatic

**Contracts.** Make ownership and caller expectations visible in ordinary Rust: who owns a value, who may mutate it, what absence and failure mean, and what crosses a task boundary. Identify those before changing representation. Honor supplied requirements and preserve settled choices outside the requested change; resolve only what the task leaves open.

Borrow through slices, string slices, and paths when ownership is unnecessary; move owned values when responsibility transfers, and a function that needs ownership takes it rather than borrowing and cloning; let lifetimes describe actual relationships. Prefer owned data in structs unless a borrow is worth a lifetime on every container. In application code take concrete types rather than impl Into or impl AsRef; those pay off in widely used libraries. Before sharing mutable state, identify the invariant requiring it. Keep independent state with its owner; choose partitioning or synchronization that preserves atomicity and resource bounds. Before a clone, an Arc, or a Mutex introduced to satisfy the borrow checker, inspect the data flow and the scope of the borrow: a shared owner that exists only to appease the compiler hides the real owner. Prefer unique ownership: Arc, Rc, and interior mutability are for sharing the design actually needs, and &mut self says more than a hidden lock. Move out of a &mut place with mem::take or mem::replace rather than cloning, and tie cleanup to a value with Drop so it runs on every path, including early return and panic. Cloning an Arc shares an allocation, not a synchronized mutation, and a guard held across an await is a contention and deadlock surface.

Choose enums for mutually exclusive alternatives: a status, phase, or flag beside fields valid only in some states becomes one enum carrying those fields, so the compiler rejects what a comment could only ask for. Keep facts that vary independently as separate fields. Parse at the boundary: turn raw input into a type that proves what was checked and pass that type inward. Give quantities and identifiers that can be swapped in one signature distinct newtypes; a type alias does not separate them. The readiness handle, the problem code, and the secret string show these distinctions here. An argument unreadable at the call site, such as a bare bool, becomes an enum or two functions; prefer named fields to tuples outside very local code. A field under an invariant stays private behind a constructor; a field with no invariant needs no getter. Use the std type for the concept, such as Duration or PathBuf. Encoding states in types moves wrong-order errors to compile time but has trade-offs, so weigh it against an enum. Use Option and Result to preserve absence and failure; never encode either in a sentinel value. When a type promises validity, trace every construction and mutation path, including conversions, deserialization, defaults, and exposed fields: each must preserve its invariant. A validating constructor alone does not close those paths. Raw input types may remain unchecked until their existing validation boundary.

Add standard conversion and comparison traits when their semantics fit. Implement the standard trait rather than a custom method with its purpose, From rather than Into, and TryFrom rather than a lossy as cast where a value may not fit; reserve Deref for smart pointers and operators for their mathematical meaning. Derive rather than hand-write an equivalent impl. Every public type is Debug, and types meant to be read are Display; hand-write them only to redact. Application code adds other traits when needed, while a published library implements the common ones eagerly because the orphan rule stops users from adding them. When identity or ordering changes, check agreement among implemented PartialEq, Eq, PartialOrd, Ord, and Hash, especially when mixing derived and manual implementations. For Ord, comparison returns Equal exactly when equality holds, and partial comparison agrees with total comparison; equal values hash equally when Hash exists. Do not add ordering or hashing merely to complete the trait set.

Library crates expose typed errors and preserve the cause through a source; only the composition root turns an error into an exit code. Keep Display operator-readable and free of secrets. Values that cross a spawn need to be Send and owned for the task's lifetime; prefer giving a task the data it needs over widening lifetimes. Public types are Send and Sync where possible. A trait stored as a trait object returns a boxed future, as the probe trait does; a trait used only generically may use an async method.

Use iterators for readable transformations and loops for clearer stateful control flow; collecting changes memory use. A combinator earns its place when it names what happens, such as any; long chains with conditionals or side effects become loops. A queue is a VecDeque; a sorted or range-queried map is a BTreeMap. Preserve ordering and byte versus text distinctions, and decide overflow explicitly where callers control the values. Unsafe code is forbidden in this workspace and compilation is not a soundness proof; a need for unsafe reopens the design rather than the lint.

Names state cost and ownership: as_ is free, to_ is expensive, into_ consumes. Getters omit get_, iterator methods are iter, iter_mut, and into_iter, and error types keep one word order. Avoid abbreviations an outsider would not know.

For review, explain the contract issue and the smallest justified change without editing files. For implementation, finish with formatted code and focused checks for the behavior or type contract affected. Avoid unrelated modernization or abstractions that obscure the operation; neither a clone nor a shared owner is wrong merely by its spelling.
