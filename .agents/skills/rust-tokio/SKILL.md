# Rust Tokio

**Ownership.** For the affected work, identify who admits it, observes its failure, requests cancellation, and waits for completion. Honor supplied requirements and preserve settled choices outside the requested change; resolve only what the task leaves open.

In this service, register process-lifetime work with bootstrap's existing Background owner and a root child cancellation token. The parent observes early completion and panic, requests cancellation, then joins within its existing deadline. A dropped spawn handle leaves failure and completion unobserved. The service's BackgroundRegistration capability lets feature managers join that ownership without creating another lifecycle. A standalone program assigns those responsibilities to its existing parent or entry function without importing bootstrap or creating a framework. Cancelling a parent token cancels its children, never the reverse.

Every await can drop the future, so keep invariants intact across it; a cancelled future holding an async lock can leave shared state half-updated. Select drops losing futures it owns; a borrowed future can remain with its owner. Check the exact operation: read is cancellation-safe, while read_exact or write_all may leave partial progress. Dropping a pending mpsc send loses its owned value, not a delivered message; retain the value separately if cancellation must preserve it. Cancellation safety also includes queue position. Biased selects poll in order; they are not an atomic stop-admission barrier. Use std::sync::Mutex for short critical sections and tokio's only when a guard must span an await. Keep data that must stay consistent under one lock, do not return a guard to a caller, and recover from poisoning only for a stated reason. To share a resource across tasks without holding a lock over await, give it to one task and talk to it through a handle. Treat SeqCst as a warning sign and choose each atomic ordering for a stated reason. Under a lock, inspect callback reentry, lock order, and blocking work even without await; shorten the critical section only while preserving atomic invariants.

In this service, use docs/architecture/runtime-lifecycle.md for business-work admission and lifetime. Trace synchronous calls made by async handlers and workers: a database query, transaction commit, or filesystem sync remains blocking under an async mutex or wrapper. Put the complete blocking operation behind the existing blocking execution owner or a supported async adapter; protect its transaction and lock scope there. Keep cheap bounded computation inline. Distinguish sustained CPU work and loops over immediately ready futures; an await alone does not yield. Bound each poll's work and arrange a wakeup when returning Pending. Yielding does not make blocking I/O nonblocking. Tokio's shared blocking pool also serves file and DNS operations; worker-count tuning does not replace admission.

Before submitting blocking or CPU-heavy work, bound admission and move its capacity permit into actual execution until it ends or unwinds. Choose admission wait or rejection from the feature's accepted budget. Keep an owner observing completion and panic beyond waiter timeout; request cooperative cancellation and account for residual execution during shutdown. A started spawn_blocking closure survives handle abort and timeout, so a cancelled request must not release its capacity early. When waiter and execution lifetimes differ, read the [execution-lifetime example](references/execution-lifetime.md). A retried job can overlap it and still needs its effect and fencing rules. Bound channels and queues with the work they feed, and signal with watch, oneshot, or Notify, not a sleep loop. Use tokio::time::timeout for a deadline on one future, and prefer async fn to returning impl Future unless a trait or setup outside the future requires it. Generic serialization and formatting callbacks remain trusted synchronous code: callers bound their source, cost and concurrency; a byte-limited writer cannot preempt callback computation.

Use tokio's Instant and interval for paused-clock control; maintenance loops delay missed ticks rather than burst. The process owner retains signal streams for their required lifetime; this service's bootstrap owns them. The entry function owns runtime shutdown: shutdown_timeout stops waiting, but running blocking closures can survive until process exit; implicit runtime drop may wait indefinitely. Keep provider shutdown off Tokio workers and within its existing budget.

For review, name the owner and the termination path for every spawned task and every held guard without editing. For implementation, prove completion by joining a task or awaiting a change notification, never by sleeping; keep paused-clock tests deterministic and leave no running task behind a passing test. Expand beyond the affected path only for a concrete risk or a required project check.
