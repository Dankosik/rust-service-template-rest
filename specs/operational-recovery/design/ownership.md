Owner-local Rust checks stay in the existing source file's `#[cfg(test)]` module.
Executors may add a private test-only control inside those modules for the
accepted lifecycle boundary; that does not authorize a shipped toggle, public
`test-support` API, new fixture binary, separate top-level test binary or new
library. Any such requirement reopens the narrow ownership decision first.
No edits to `infra-postgres` runtime policy, gRPC/HTTP wire implementation,
generated protobuf/OpenAPI, runtime config, schema or provider libraries are
preselected; a concrete in-scope defect there returns to this design owner.

## Reuse selection and necessity

| Non-mechanical responsibility | Selected reuse rung and authority | Strongest rejected substitute | Parity/proof boundary | Upgrade/reopen condition |
| --- | --- | --- | --- | --- |
| H/S/W completion loss | Existing health watch state, Tokio timer and both existing Background owners at the pinned workspace resolution | Independent watchdog framework | All existing generic health recovery, ordinary failed-round recovery, task-return/panic and cleanup custody remain authoritative alongside R1 | Accepted watchdog semantics exceed readiness's actual completion authority |
| C useful-work composition | Current integration runner, admitted SQLx pool, real `Server` and retained generated Echo service | New shipped business route or broad fixture framework | Canonical adapter/wire calls with real dependency; separate actual-root proof | An accepted consumer cannot be mounted with the current composition owners |
| L mutex/custody | Python stdlib native flock, exclusive file creation, subprocess/session and private pipe; current shell entrypoint | Extra custodian daemon or PID-based stale deletion | Isolated mixed legacy/new admission, generation and actual surviving child custody | Unattended escaped-resource recovery or a new OS becomes required |
| D daemon completion | Existing Docker/Compose owners plus two internal generation-metadata ticket operations | Inferring completion from shell success or adding a generic resource manager | Pending before external effect; native scoped terminal acknowledgement; no release/pass on missing evidence | A new external work class lacks a named existing owner |
| B compiler cache | Maintained sccache 0.18.0 as optional tool plus Cargo native wrapper contract | Custom artifact-cache logic or global install/config | Native cache mode/version/identity and actual observed stats, ordinary uncached correctness retained | Upstream compatibility defect, host absence or unsupported wrapper composition |
| V resource/receipt | Existing verifier with narrow Python context/OS resource projection | General machine telemetry service or independent receipt engine | Candidate/plan/environment identity and truthful pending/resource result | New output execution inputs cannot be represented safely |

No dependency direction or semantic crate ownership is moved. Health already
owns readiness state; roots already own process policy; integration-tests already
owns real database observations. The new script helpers each have one present
responsibility: L's OS custody or B's command context/resources. Deleting either
would return that responsibility to shell code that cannot directly provide
native portable flock or structured safe context extraction. No abstraction is
justified solely to shorten a caller.
