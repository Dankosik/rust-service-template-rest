# Transformation and ownership inventory

Status: ready. This is the closed inventory for [system design](system.md).
An implementation may split a listed file mechanically, but a new semantic
owner or omission reopens Design. All future filenames below are planned paths.

Generated owner paths are `.codex/config.toml`, each selected adapter's agent
directories (and Grok roles), and Claude/Qwen skills links. Settings are two
managed-leaf exceptions. Source preflight/purity derives those paths and
generator/helper closure from one constant adapter map in template_state.py.
That map does not supply full-sync ownership; the manifest remains sole source
for copied whole files. No template.lock, Cargo, runtime, config, OpenAPI,
migration, service Make/profile file, workflow activation, deny/gitleaks policy,
architecture, README, CODEOWNERS, LICENSE, CONTRIBUTING, or acceptance file is
copied by sync.

Instruction-only subset is AGENTS, canonical `.agents` rows, adapter input rows,
all docs rows above, and their selected generated/settings owners. It excludes
Makefile, make/, tools/, manifest and every scripts/ row. Source helpers still
participate in snapshot admission and execute from that snapshot.

Before AGENTS becomes portable, move its repository description, crate facts,
toolchain facts, command table values and roadmap/stage-specific statements to
existing local docs; retain authority and general decision/routing methods and
link to those docs. Preserve existing policy semantics. Portable validation
docs/router similarly delegate local gate inventories and CI activation to
local command/CI/validation owners. Skills retain expertise; actual hardcoded
availability/defaults become conditional on existing local architecture/config
owners. No change to role authority, macro phases, or validation budget meaning.
Local paths referenced by selected portable docs form a required-authority set
in template_state.py, validated before sync writes. Keep this set minimal and
derived from actual references; optional source-history links are not required.

Makefile gains the exact literal-input capture preamble described in system.md,
then portable includes: service.mk first (data before method), template.mk
second, source.mk optional last. service.mk must contain no standard
target override or arbitrary include/evaluation directive for full-sync
admission. Parse its static declaration/recipe headers as data; reject conflicting
standard targets including pattern/multi-target forms. Preserve permitted
nonstandard service recipes verbatim; never execute the file during sync.
Standard target names come from portable make/template.mk's declared registry,
not a second policy list. Legacy root Makefile with extra recipes refuses full
sync, while instructions-only ignores it. The local profile include is opened
by template.mk only during normal authorized Make execution, never sync.

Source-only retained by template, removed from initialized outputs:
`make/source.mk`, initializer matrix/purity/sync fixture programs and data under
`scripts/tests/template-*`, `scripts/ci/template-init-check.sh`, `specs/`,
`docs/roadmap.md`, and source-specific eval fixtures under `evals/`. The initial
entry/helper/profile data remain in outputs to support lock-aware one-shot
replay but are service-owned and excluded from full-sync ownership. Source-only
initializer target is therefore not in source.mk: its standard entry remains
available in the initialized service through portable template.mk and its
retained local initializer. Full sync preflights that helper's presence.

Purity is a source-only check: validate manifest safety/nonemptiness/exclusions,
generated/input coverage, required sync propagation, profile-marker absence,
identity constants outside explicit provenance fields, and no owned path that
would override local policy. Semantic portability remains independent review;
the marker/string checks do not establish it alone.
