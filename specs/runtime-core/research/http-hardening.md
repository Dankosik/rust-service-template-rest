# Lane report: hardened HTTP chain on axum 0.8 / tower / hyper

Raw research lane output, 2026-09-17. Verified against crates.io and the
crate sources of axum 0.8.9, axum-core 0.5.6, tower 0.5.3, tower-http 0.7.1,
hyper 1.11.1, hyper-util 0.1.20, axum-server 0.8.0, problemdetails 0.7.0,
problem_details 0.10.0, tower_governor 0.8.0, plus GitHub issues. Decisions
are consolidated in [synthesis.md](synthesis.md).

Versions (crates.io, 2026-09-17): axum 0.8.9 (2026-04-14, MSRV 1.80) ·
tower 0.5.3 · tower-http 0.7.1 (2026-08-31; 0.7.0 on 2026-06-15 was

## Layer order

Facts (axum 0.8.9 `docs/middleware.md` and source): `Router::layer` wraps
all routes and the fallbacks; `Router::route_layer` wraps only matched
routes and panics with zero routes. Repeated `.layer()` calls nest
bottom-to-top; inside `tower::ServiceBuilder`, layers run top to bottom.
Middleware added with `Router::layer` runs after routing (`MatchedPath`
available); middleware wrapped around the whole router runs before routing.
`Router::layer` requires the error type to be `Into<Infallible>`, so
`HandleErrorLayer` must sit above `load_shed`/`timeout`.

```rust
Router::new()
    .merge(routes)
    .fallback(problem::not_found)
    .method_not_allowed_fallback(problem::method_not_allowed)
    .layer(ServiceBuilder::new()                                  // top = outermost
        .map_request(request_id::strip_invalid)                  // custom
        .layer(SetRequestIdLayer::x_request_id(MakeRequestUuid))
        .layer(PropagateRequestIdLayer::x_request_id())
        .layer(SetResponseHeaderLayer::overriding(X_CONTENT_TYPE_OPTIONS, nosniff))
        .layer(TraceLayer::new_for_http().make_span_with(otel::make_span))
        .layer(middleware::from_fn(access_log::one_line))        // custom
        .layer(HandleErrorLayer::new(middleware_error))          // BoxError -> Problem
        .load_shed()                                             // outside the limiter
        .layer(GlobalConcurrencyLimitLayer::new(max_in_flight))
        .timeout(request_timeout)                                // -> Elapsed
        .layer(CatchPanicLayer::custom(problem::from_panic))
        .layer(middleware::from_fn_with_state(max_body, body_limit::enforce)) // custom 413
        .layer(DefaultBodyLimit::max(max_body)))
```

Rationale: request id first so spans, logs and error bodies can read it;
nosniff and propagate near the top so 503/504/500 from lower layers carry
them; access log inside the span but outside the shedder/timeout so rejected
requests are logged with their real status; `CatchPanic` inside the timeout
so a panic becomes 500 instead of racing the timer; body limit innermost.
`HandleErrorLayer` extractors are `FromRequestParts<()>`, so
`Extension<RequestId>` is the way to reach the id.

## Connection-level limits

- `axum::serve` (0.8.9): builds `auto::Builder`, calls only
  `http2().enable_connect_protocol()`, sets no timer. Because no `Timer` is
  set, hyper's default 30 s `header_read_timeout` is disabled (`warn!` only):
  Slowloris out of the box (axum #2741, closed as hyper's job).
  `ListenerExt::tap_io` only pokes the socket. `with_graceful_shutdown` has
  no deadline.
- `axum-server` 0.8.0: `Server::http_builder()` exposes the hyper-util
  builder, `Handle::graceful_shutdown(Option<Duration>)`,
  `Handle::connection_count()`, TLS acceptors. Also sets no timer by default
  and has no connection cap (unbounded spawn per accept). Single maintainer.
- Hand-rolled loop = axum `examples/serve-with-hyper` + hyper-util
  `examples/server_graceful.rs`: `accept` → `TokioIo` →
  `TowerToHyperService::new(router.clone())` →
  `serve_connection_with_upgrades` → `graceful.watch(conn.into_owned())` →
  spawn.
- hyper 1.11.1 h1: `max_headers` (default 100 → 431); `max_buf_size`
  (default ~400 KiB, min 8192) caps head parsing (431 on overflow) and body
  read chunks — the only "max header bytes" knob for HTTP/1.
  `header_read_timeout` starts on connect (1.4.0) and restarts when the
  connection goes idle (1.6.0), so for HTTP/1 it is both header and
  keep-alive idle timeout: one knob. HTTP/2 has no idle knob.
- Open bug: the `auto` builder sniffs the h2 preface before the http1 timer
  exists, so a client that connects and sends nothing is never timed out
  (hyper #3756 open; hyper-util PR #294 closed unmerged). Works with
  `http1_only()` + `serve_connection`. Workaround: `timeout(header_timeout,
  stream.peek(&mut [0u8; 1]))` before handing the socket to hyper.

Recommendation: hand-rolled accept loop over `auto::Builder` with
`TokioTimer`, `TowerToHyperService`, `GracefulShutdown`, a
`Semaphore(max_connections)` whose `OwnedSemaphorePermit` lives in the
connection task, the `peek` guard, and `timeout(drain, graceful.shutdown())`.
`GracefulShutdown::count()` reports live connections. The "5 s header / 60 s
idle" split is not expressible for HTTP/1 without a custom IO wrapper; pick
one value or write the wrapper. `axum-server` only if in-process TLS is
needed; `axum::serve` only behind a proxy that enforces these limits.

| `http-problem` | 0.3.0 / 2023 | no | — | Skip |

Recommendation: a hand-written `Problem` type (~60 lines) with `code`,
`request_id`, `invalid_params` first-class, `IntoResponse` setting
`application/problem+json` and `Retry-After`; `problem_details` with a fixed
`Ext` is the acceptable crate alternative.

## Gotchas

1. `axum::serve` has no timer → default header timeout off.
2. `auto` builder + silent client never times out (hyper #3756).
3. One knob for header and idle timeout on HTTP/1.
4. `max_buf_size` min 8192; `header_read_timeout(Some(_))` without `timer()`
   panics at `serve_connection`.
5. `ConcurrencyLimitLayer` in `Router::layer` is per-route; use `Global…`.
   `LoadShed` wraps the limiter.
6. `tower::buffer` queues; avoid.
7. tower-http `TimeoutLayer::new()` deprecated (408); `with_status_code`
   gives an empty body. No request timeout covers streaming bodies.
8. `CatchPanic` is a no-op under `panic = "abort"`.
9. `MatchedPath` absent for `Router::fallback`, present for 405, invisible
   through `nest_service` and for middleware around the whole router.
10. `Router::layer` vs `route_layer`: only `layer` covers fallbacks.
11. `Allow` on 405 is automatic unless the response already has one.
12. `CorsLayer` intercepts every `OPTIONS`; omit the layer for fail-closed.
13. Body-limit bodies are `text/plain` without the custom wrapper.
14. `HandleErrorLayer` extractors are `FromRequestParts<()>`.
15. `RateLimit<S>` is not `Clone`; use `tower_governor` later.
16. tower-http 0.7 migration: `tokio`/`async-compression` features removed;
    `trace` events parented to the request span.
17. Adding `problemdetails` duplicates tower-http.
18. Unverified: `axum-tracing-opentelemetry`/`tower-otel` APIs,
    `tower_governor` key extractors beyond README, axum #3216 fix version.
