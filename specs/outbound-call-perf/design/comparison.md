# Remote comparison and teardown

This defines the synthetic performance proof for [D7 and D8](design.md#d7--isolate-conditional-changes-from-the-base-candidate) and the final evidence for [R7 and R8](../spec.md#r7--conditional-alternatives).

## Equivalent artifacts and trials

- Freeze the pre-change source parent in [the design](design.md) as baseline. Build it, the baseline plus D1–D6, isolated D7 variants, and the final selection in the same Linux release profile with the same locked graph, toolchain, target, build flags, allocator and features. Use a shared experiment driver and fixtures and retain their source identity. Test-only instrumentation belongs in the experiment overlay, outside production configuration. Run the performance comparison on the authorized Droplet only.
- Use the public prepared/authenticated call paths and warmed clients, TLS connections, and credentials. Use disposable local synthetic trust and credentials, with distinct caller and fixture processes. Run the HTTPS token endpoint and HTTP/gRPC resource peers on loopback only. Separate caller and peer CPU accounting and, where available, assign them distinct fixed CPU sets. Record Droplet size, machine model, worker and process placement, kernel/image, toolchain, binaries and build settings, payload and concurrency, telemetry mode and traffic shape. Keep warm-up and cold grant/connection setup outside the timed population. The early refresh request still runs during the designated active-refresh measurement.
- Interleave matched repetitions on one host, balancing baseline/candidate first, with the same warm-up, observation/trace setup, request semantics, response consumption, and per-window number of offered calls. Record independent repetitions and ordering, per-run counts and variation. Carry the measured inputs and raw results with the summary. Avoid pooling removed outliers or combining scenarios with different work. A pilot may adjust the window size and repeat count to fit the budget. Apply the resulting protocol to both sides and record it.
- For each homogeneous timing window, collect caller process CPU delta (user plus system) and completions grouped by outcome. Report CPU per completed call alongside offered, successful, refused, failed and timed-out/cancelled counts and provider/resource counts. Report wall latency distribution and p99 with sample size. Count peer connections separately when evaluating transport effects. CPU includes work attributable to the caller process, including its background refresh machinery. Fixture CPU, build, phase transition, reporting, and warm-up do not enter the timed numerator. Collect checksums or byte/status counts so changed response consumption is detectable. Use independent measurement windows if intrusive memory or connection instrumentation would distort timing, and match that instrumentation within each comparison.

| Workload | Distinguishing work and counters |
| --- | --- |
| Authenticated warm service hits, one caller and 64 concurrent callers, each before and during early refresh | Share a credential source and warm transport, with room for all 64 to progress without measuring fixture admission limits. Record p99 and caller CPU per call separately for all four cells. Begin the refresh cell only after the peer has positively observed the replacement grant and is holding its response. Finish the measured window while the old token is still eligible and before releasing the replacement response or hitting the provider cutoff. The timing report distinguishes the fixed-URL benchmark workload from diagnostic alternate spellings, artificial retained response lifetimes, and paused-peer orchestration. It attributes results only to workload cells actually exercised. Behavior checks can use the existing proving surfaces in [the design](design.md#obligation-trace).

## Conditional comparisons

### Hyper Host insertion

Variant: set `set_host(false)` on the existing private transport builder. All sends enter through prepared admission, which refuses caller Host and sets the configured value before trace injection and request dispatch. The locked Hyper Util checkout only fills a vacant Host entry. Disabling that branch preserves the same transport URI, pool key, Host bytes and retry configuration. Unstarted retries recover the same request headers and restore the original URI. A future bypass of prepared admission would reopen this assumption. [HTTP admission](../../../crates/infra-outbound-http/src/policy.rs), [transport](../../../crates/infra-outbound-http/src/transport.rs), [checkout and retry](../../../vendor/hyper-util/src/client/legacy/client.rs).

Compare canonical and admitted alternate authorities, reused connections including unstarted retry, and caller Host refusal. Check wire Host and URI form, peer requests, established connections and caller CPU. The saving is the URI clone and occupied-entry lookup per eligible checkout. The cost is explicitly relying on the prepared request's Host invariant. Keep the variant only if equivalent behavior and a repeatable gain are established. Keep the existing setting if the benefit is unresolved or any supported send can bypass the invariant. An incidental maximal-map panic is outside the supported contract.

### Single HTTP data frame

Variant: keep the first nonempty `Bytes` until EOF, switch to the existing bounded copy/append behavior on a second nonempty data frame, and return the original first frame only for the successful one-frame result. Keep the size hint rejection and `Limited` traversal, including trailers, EOF, errors and pre/post-consumption context checks. Empty data frames must not change framing or cause an allocation that defeats the empty-body case. [Buffer owner](../../../crates/infra-outbound-http/src/lib.rs).

The saved copy/Vec allocation can be outweighed by receive buffer retention. Compare empty, one-frame and multi-frame paths for CPU/allocation, and separately compare peak/live retained backing with many responses retained for identical recorded lifetimes. Include small one-frame bodies delivered from large reads and a short-hold control alongside large responses. Ensure the memory evidence distinguishes still-live backing from allocator-cached freed pages, e.g. a matched live heap capture attributed to receive and response allocations, corroborated by process memory if useful.

Preserve the current response body ownership bound: holding a completed one-frame result costs an allocation proportional to its visible bytes, bounded by the configured body limit apart from allocator rounding and fixed metadata, independent of the transport read allocation. Locked Hyper's `proto::h1::io::MemRead::read_mem` splits the read slab and `Bytes` and `BytesMut` splits can share storage. `Limited` bounds visible bytes. A one-byte body can therefore retain a transport slab larger than the limit. Unconditional retention is a comparison variant only. Keep bounded copying unless a simple source-verified way to enforce the backing bound becomes available and matched evidence also shows equivalent behavior and a repeatable gain, with no increase beyond measurement noise in retained live bytes and peak live bytes in the adverse case. A favorable CPU or memory result from one workload cannot remove the source-derived incompatibility.

### Shared service-cache access

Variant: use the already locked `parking_lot::RwLock` for `Cached`. Select and clone the still-eligible current token under a shared guard. For refresh-due hits, drop the read guard before acquiring exclusive access. Under the write guard, recheck the selected token's identity, eligibility and refresh schedule, pending flag, and failure deferral before mutating schedule or enqueueing. If concurrent replacement or rejection prevents scheduling, return the original selection through the existing outer activity and expiry checks. All replacements, retry scheduling and failure updates stay exclusive. Keep lock scopes bounded and synchronous, the existing serial fetch lock and after-lock reuse recheck. [Service acquisition](../../../crates/infra-oauth2-client-credentials/src/credentials.rs), [token eligibility](../../../crates/infra-oauth2-client-credentials/src/token.rs).

Compare both sides at one and 64 callers before and during gated refresh. Include the refresh-due decision and closure/rejection/replacement/expiry in behavior evidence, including unchanged provider and resource work. Concurrent reusable reads may save contention while a due hit can take two guards and increase writer delay. Compare p99 and CPU and confirm refresh completion and timely publication in the same work. Keep the mutex if gains are inconclusive, cadence or timely writer progress regresses under the tested load, or the selected-token semantics or grant counts differ.

### Exact authority before normal admission

Variant: after the same scheme and presence checks, compare request authority bytes with the canonical configured Host spelling. An exact match is eligible only where canonical configuration already proves the same host/port policy with no userinfo. All other inputs fall through to D4. Keep the request URI verbatim. Compare canonical-only work, accepted alternates and a disclosed mixed diagnostic population for caller CPU, plus wrong scheme/port/origin and userinfo refusals. Include case variation, explicit default port, empty port and bracketed IPv6 in the equivalence reasoning. This may avoid a host split and port scan on hits while adding one byte comparison on misses. Keep D4 alone if comparable evidence does not support the benefit or the exact fast branch admits anything newly. [Origin owner](../../../crates/infra-outbound-http/src/policy.rs), [shared origin rules](../../../crates/shared-rules/src/uri.rs).

### Default-port pooling

Retain the supplied URI and existing pool identity. The vendored transport extracts scheme and authority into its pool key and uses that identity to reconstruct the connection URI. Both implicit and explicit default port spellings are admitted by policy and can allocate two buckets, but one stable URI spelling does not create alias fragmentation even if that spelling is explicit. Synthetic variant testing of admission does not establish a recurring target workload requiring alias collapse. A rewrite could change CONNECT authority form and the identity used by DNS/fixture resolution, TLS and retry. The usual canonical Host header does not remove those risks. Reopen only with observed workload mixing, excess connections or TLS handshakes attributable to the aliases, and equivalent DNS/TLS/routing/retry/wire evidence. Record this disposition as source-derived unless actual triggering workload evidence becomes available. [Origin policy](../../../crates/infra-outbound-http/src/policy.rs), [vendored pool dispatch](../../../vendor/hyper-util/src/client/legacy/client.rs), [source review](../research/review.md).

## Decisions and evidence

For each measured option, carry both the result and its cost before choosing. A comparison supports keeping an option when repeated paired deltas favor it beyond observed run-to-run variation for its relevant workload and the applicable behavior and resource evidence agrees. Record the distribution, observed noise, affected conditions and any contradictory cells instead of requiring a fixed percentage effect. Inconclusive conditional options retain the ordinary implementation. Compare the final selected artifact against the original baseline on the required matrix, since the optional changes can interact with one another and D1–D6. Keep measured results, source deductions, skipped comparisons, and limits distinct. No observed saving is assumed in the design.

## Cost and teardown

1. **Before create.** Verify live CPU-optimized size availability, applicable charge granularity, base price and extras. Derive a worst-case spend deadline from the total US$5 ceiling, reserving an explicit margin for export and deletion retries based on verified billing. Persist an off-Droplet recovery receipt before the request. Record the exact unique Droplet name with a task nonce, expected region and size, rate, permitted create window, cleanup cutoff, and non-secret locator for the authorized control-plane access. Check that the identity is absent before submitting the one create request. Establish a bounded off-Droplet cleanup owner that can run at the cutoff even if the initiating agent or SSH session exits, using the persisted receipt and existing access. If setup, useful measurement and teardown cannot fit, or the independent cleanup path is unavailable, stop before create and return the external input to Intake.
2. **While active.** Write the provider ID to the same durable receipt as soon as it arrives. After interruption or an ambiguous create, resume from the receipt. Reconcile the original create and exact task identity under the expected account, region, size and create window before recording an ID. Do not submit a second create. Build and run only on the reconciled ID. Monitor elapsed spend with setup included. Export raw receipts incrementally to the task worktree or the task's evidence location and verify they can be read there. Stop workload in time to preserve the cleanup margin. Retain partial evidence and state the limit if the run cannot finish. Use synthetic secrets only and omit them from captures.
3. **Close.** After confirming the last saved evidence or recording the partial results at the cleanup deadline, delete the one task Droplet by its recorded ID using the control plane. If the primary controller exits, the cleanup owner reconciles any outstanding create and applies the same deletion procedure by the cutoff. The cleanup owner uses the verified results already saved off-host and attempts a final export only within the reserved margin. Verify deletion from a terminal provider operation or authoritative absence of that same ID using a functioning authenticated read. A power-off, dropped SSH session, or ambiguous API error is insufficient. Recheck provider state after an ambiguous write and retry only while the exact owned resource is confirmed present. If provider closure remains unverified, report the exact status and ongoing cost exposure. Preserve receipts with timing, artifact identities, spend calculation/provider billing where available, and non-secret deletion response/status. Retire the task's cleanup owner after verified closure.
