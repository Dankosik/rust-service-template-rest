## Key decisions

### D1 — Select a reusable service token before setting up waiters

- **Choice.** Keep the initial active check for all sources. If the source is service credentials and Tokio's cooperative budget is available, perform the service's inner active check and run its synchronous reuse-and-schedule decision only if that check succeeds. A hit goes through the existing final activity and token expiry checks. A failed speculative check, an exhausted budget, a miss, or an exchange source takes the existing biased stop/registration-close/acquisition select. This keeps directly observed context stops and results from other branches in their existing priority order. Closure or acquisition results still pass the fresh final activity check before being returned. Leave the inner service check and second lookup in the select path so a waiting caller can reuse a token populated after its first miss. No cache guard crosses a suspension.
- **Decisive constraint.** A reusable service token can be returned with bounded synchronous work despite an in-flight early provider refresh. The existing select checks cooperative budget without spending it and arranges a wake at exhaustion. `tokio::task::coop::has_budget_remaining` lets the hit bypass its timer, cancellation waiters, and watch receiver clone. At exhaustion the original select owns the cooperative yield and stop ordering. Exchange cache lookup can suspend.
- **Strongest rejected alternative.** Put both kinds of cache lookup ahead of the select. A Moka lookup can suspend while its maintenance completes, which would move exchange work outside existing cancellation and close coverage.
- **Accepted cost.** A service miss can do an extra short lookup before the current wait path. The existing fetch lock, after-lock recheck, failure cache, grant execution and driver remain the same.
- **Reopen if** a matched run isolates a material cold-miss regression, a Tokio change invalidates the select’s budget behavior, or service reuse stops being synchronous. **Durable record.** None.

### D2 — Use the existing request stop check for a representable cutoff

- **Choice.** Make cutoff provenance internal to `AcquisitionDeadline`. When the cutoff is the request's primary representable deadline, the existing `RequestContext::stopped` supplies the timeout or cancellation decision. It checks the primary deadline before cancellation and then checks the extension contexts in their existing order. When the cutoff is the synthetic acquisition ceiling, check it first and return `Unavailable` if reached, otherwise evaluate request stops as today. The cutoff and its error mapping still control bounded waits and child fetch windows.
- **Decisive constraint.** In the representable case, comparing the stored cutoff first repeats the primary deadline check. Provenance matters in the synthetic case, including an unrepresentably large parent budget. The selected deadline is never reused as a clock sample across activity, scheduling, provider completion or dispatch checks.
- **Strongest rejected alternative.** Thread one time sample or a cancellation-only method through public operation/request context APIs. The existing primary check already owns the equivalent result and using it keeps the context APIs and independent observation boundaries stable.
- **Accepted cost.** The synthetic path retains the extra check. Timeout normalization for provider failures and stop precedence inside existing wait paths stay in their current owners.
- **Reopen if** cutoff construction can diverge from the request's primary deadline in the representable branch. **Durable record.** None.

### D3 — Borrow HTTP destination data through attempt finalization

- **Choice.** Give the private HTTP attempt a borrow of the client-owned `Server` for the send scope. Reuse the existing DropGuard that owns abandonment reporting, status recording after final headers, trace injection and explicit finish after disarming. Scope the borrow to the already borrowed client and request context. Recorded metric labels still own what they pass to the recorder.
- **Decisive constraint.** `PreparedRequest` already borrows the client through buffered and headers-only completion. No observer escapes that future. Status at final headers must survive every later failure and identify `AfterResponse`.
- **Strongest rejected alternative.** Move attempt reporting into a detached guard that owns clones or move explicit finish into each result branch. This repeats ownership or scatters the once-only completion rule.
- **Accepted cost.** A private lifetime ties the attempt to the client and its synchronous finalizer. Existing outer stop select, dispatch checks, post-result activity check, labels, duration and span behavior stay at their established boundaries.
- **Reopen if** an accepted operation requires an observation to outlive the borrowed client. **Durable record.** None.

### D4 — Simplify HTTP origin and empty-body preparation in place

- **Choice.** Extract `Authority::host()` once under the existing scheme/authority decision and reuse it for host and port checks. Reuse the existing canonical origin and `shared_rules::uri::http_origin_port`. Set static zero Content-Length for empty POST, PUT and PATCH, remove it for other empty methods, and preserve numeric framing for nonempty bodies. Strip caller Transfer-Encoding as today.
- **Decisive constraint.** These are changes within the single prepared-request admission/framing boundary. Accepted alternate spellings and exact wire bytes for Content-Length are already defined.
- **Strongest rejected alternative.** Use Hyper's implicit Content-Length for empty requests. That would hand the method-specific omission, replacement and zero-length behavior to transport defaults.
- **Accepted cost.** Explicit framing remains in the policy owner. The exact-authority fast branch remains subject to D7.
- **Reopen if** repository HTTP protocol or the supported framing contract changes. **Durable record.** None.

### D5 — Reuse validated gRPC method labels and defer diagnostic string copies

- **Choice.** Require `GrpcMethod` and the existing per-part length limits before consulting the registry. Bound the speculative path lookup to the largest admissible path (514 bytes, including two separators). On an exact path hit, compare both declared components with the two labels stored at verified admission. On a full-snapshot miss, return the existing fallback without taking the admission lock. On a below-capacity miss, retain full path parsing and declaration equality before insertion, with the under-lock recheck for a racing admission or saturation. Lookup precedes capacity refusal and the snapshot is append-only.
- **Choice.** Keep the two bounded diagnostic checks and pass the borrowed original path and incoming user agent in a private conversion into `opentelemetry::Value` at the existing `set_attribute` calls. The adapter only owns the conversion boundary. Do not alter span names, attribute order, tracing targets or metric admission. Keep context injection outside any span gate so the existing ambient OpenTelemetry fallback still propagates.
- **Decisive constraint.** Warm hits establish path validity by construction and still require matching metadata from this request. A full immutable snapshot proves no later admission can fill the miss. `tracing-opentelemetry` 0.34.0 checks subscriber/span availability before attribute conversion. The conversion is skipped for disabled spans and subscribers without the bridge. In a mixed subscriber that has the bridge but filters only its layer for this span, upstream may still convert before finding no per-span data.
- **Strongest rejected alternative.** Use the warm path match alone, or use a span-enabled guard around both attributes and injection. Path alone admits missing/conflicting metadata. A span-enabled guard misses no-bridge cases and gating injection loses the ambient parent. Recording native tracing fields would also expose values to other layers and move their observation boundary.
- **Accepted cost.** Valid-looking new paths can be hashed then parsed during admission. The lazy value does not eliminate the bounded validation, and may still allocate in the mixed-layer case. The append-only snapshot and global width of 256 remain.
- **Reopen if** label identity or immutable admission changes, or the locked telemetry bridge's conversion order changes. **Durable record.** None.

### D6 — Finish terminal gRPC responses before allocating stream state

- **Choice.** Retain the existing attachment sequence. The first lifetime check can replace status headers with a local stop. Otherwise inspect wire status. During initial body classification retain precedence of the selected initial outcome, an additional stop check (staged stop trailers), then end-of-stream fallback. Run the same completion for every terminal outcome, consuming observation, hook and custody. Only an initial phase already reduced to `Done` returns the empty tonic body before allocating shared stream state. Staged trailers and open bodies still use the existing wrapper, with the watcher only for an open watched lifetime.
- **Decisive constraint.** On the current `Done` path the wrapper allocates state, then tonic calls `is_end_stream`, discards it and returns an empty body. Finishing before that allocation preserves status headers, empty-body size hint and immediate release of both response body and upload/cancellation guards.
- **Strongest rejected alternative.** Return the raw body on any gRPC status header or precompute terminal state solely from `is_end_stream`. These paths omit local-stop precedence, the immediate wire hook and upload release, or can discard staged trailers.
- **Accepted cost.** Keep one completion path and the existing watcher and once-only finalization for open or staged bodies. Decoded mode still records local-stop state as before and delegates wire decoding/abandonment outcomes to the tonic observer. Transport mode still uses the selected metric status and independent wire hook code.
- **Reopen if** tonic changes its empty-body or response observer contract. **Durable record.** None.

### D7 — Isolate conditional changes from the base candidate

- **Choice.** Compare separate reversible variants against the base candidate for Host insertion, retained first frame, service-cache sharing and exact-authority admission. Use the designs and evidence conditions in [conditional comparisons](comparison.md#conditional-comparisons). Keep existing pool keys under the accepted fixed-URL workload assumption.
- **Decisive constraint.** The changes trade different costs and several overlap the same call path. Combined numbers cannot identify which alternative pays for its complexity or changes a bound.
- **Strongest rejected alternative.** Land every statically cheaper path together or use one combined benchmark alone. This would conflate allocator retention, mutex transitions, URI fallback cost and wire effects.
- **Accepted cost.** Build and compare independent variants, then compare the assembled selection with the original baseline. Discard experiments that fail equivalence or yield inconclusive benefit.
- **Reopen if** the linked deciding evidence justifies an alternative or a real mixed-authority workload emerges for pool identity. **Durable record.** None for the specified work. Reopened pool identity would need its own decision record.

### D8 — Prove equivalent work on a disposable remote host

- **Choice.** Use matched release artifacts and controlled peers on the one authorized CPU-optimized Droplet. Measure caller-process CPU and wall latency, account for completed work, and export evidence before deleting by exact Droplet ID. The [comparison and teardown](comparison.md) defines the workload, comparison and bounded recovery.
- **Decisive constraint.** Interleaved runs on one host control machine drift and keep the comparison within the task's sole authorized cloud resource. Isolating peer processes prevents fixture CPU from masquerading as caller cost.
- **Strongest rejected alternative.** Compare a local baseline with a remote candidate, or use whole-host CPU on one shared process. Neither provides an attributable CPU-per-call comparison.
- **Accepted cost.** Controlled synthetic evidence says what changed under the recorded conditions. It cannot establish a production performance or readiness claim.
- **Reopen if** the authorized Droplet or reliable deletion margin cannot fit within US$5. Return the external authority gap to Intake. **Durable record.** None.

## System flows, invariants, and failure semantics

- **Credential dispatch.** Resource origin checks and grant/subject admission precede credential acquisition. Reuse is linearized at the eligibility decision on the selected token. Later cache replacement or token rejection leaves that caller's selection intact, while activity and actual expiry are checked again before dispatch. Demand waiters retain context cancellation and deadlines, registration-close observation, and service refresh-driver closure checks at the current boundaries. The service uses one fetch lock, a capacity-one refresh queue, cache failure deferral and driver shutdown as before. Exchange cache bounds and request-only token settlement stay unchanged. [Acquisition](../../../crates/infra-oauth2-client-credentials/src/credentials.rs), [exchange](../../../crates/infra-oauth2-client-credentials/src/credentials/exchange.rs), [token](../../../crates/infra-oauth2-client-credentials/src/token.rs), [HTTP caller](../../../crates/infra-oauth2-client-credentials/src/http_client.rs), [gRPC caller](../../../crates/infra-oauth2-client-credentials/src/grpc.rs).
- **HTTP lifetime.** Prepared admission installs the canonical Host and evaluates context before attempt creation. The attempt owns one terminal decision through response consumption or drop and retains the final-headers status across body failure. Headers-only returns on final headers. Buffered completion still checks the context during body traversal and at the existing final check, with byte limits, EOF, transport error classification and pre-write-only reused-connection retry unchanged. [Client](../../../crates/infra-outbound-http/src/lib.rs), [observation](../../../crates/infra-outbound-http/src/observe.rs), [policy](../../../crates/infra-outbound-http/src/policy.rs), [transport](../../../crates/infra-outbound-http/src/transport.rs).
- **gRPC lifetime.** An opening permit and remaining context control admission/dispatch. Response attachment either finishes immediately, delivers staged stop trailers, or transfers ownership to the open stream. No additional watcher, lease or task is created for already-terminal responses. Watchers, upload custody, idle stops, abort-on-drop, wire status hooks and decoder abandonment follow the current boundaries. [Client](../../../crates/infra-outbound-grpc/src/client.rs), [response and upload custody](../../../crates/infra-outbound-grpc/src/call.rs), [vendored tonic observer](../../../vendor/tonic/src/client/grpc.rs).
- **Operator signals.** Existing error classes/status codes, attempt and terminal counts, histogram fields, traces, cache refusal and refresh warnings remain at their existing owners. The experiment's per-scenario call counts, resource/peer counts, measurements and teardown evidence are task artifacts.
- **Deployment impact.** None. There is no schema, production trust/config, release or rollout change. Experiment TLS and credentials are ephemeral.

## Rust architecture, seams, and ownership

- **Semantic owners.** Extend the existing OAuth acquisition/refresh owner, HTTP policy/attempt and gRPC observation/custody owners in their current `oauth`, `outbound-http` and `outbound-grpc` roles. Keep `operation-context` as the lineage authority and `shared-rules` pure. No new production dependencies, features, cross-crate interfaces, configuration, generated output, or template profile coupling. D1 preserves the existing waiting path for real suspension. D3 removes only the observation's redundant destination clone. D6 removes only the construction of a lock-protected state that has already reached `Done`.
- **Deep modules and seams.** Callers still exercise public credential, prepared HTTP and gRPC paths. Private typed cutoff provenance and the borrowed attempt preserve their ownership rules without forwarding through another public layer. The bounded attribute conversion uses the existing `Value` trait conversion. Removing it would require eagerly owning strings or changing how fields reach subscribers. Locked timer, body and synchronization types remain implementation details.
- **Verified anchors.** `RequestContext::{deadline,stopped,wait_stopped}` and `OperationContext::stopped` preserve deadline and extension precedence. Tokio 1.54.1 selects with a cooperative budget check and `watch::Receiver::changed` awaits cooperatively. Moka 0.12.16 uses asynchronous lookup. The borrowed HTTP attempt only holds shared references to Send/Sync client/context state it already uses across awaits. `http` 1.5.0 has static HeaderValue support and `bytes` 1.12.1 shares split backing allocations. `hyper` 1.12.0 splits its HTTP/1 read buffer. Vendored `hyper-util` 0.1.21 owns Host insertion, URI rewriting, and retry. `tracing-opentelemetry` 0.34.0 owns dynamic attribute conversion to `opentelemetry` 0.33.1 values, and SDK 0.42.1 supplies ambient context fallback. The vendored `tonic` 0.14.8 `Body::new` short-circuits through `is_end_stream`, and `Body::empty` preserves the after-finalization body representation. [Dependency lock](../../../Cargo.lock), [architecture rules](../../../quality/architecture.json), [repository architecture](../../../docs/repo-architecture.md).
- **Shared mutated surfaces.** None across manifests, shared context/URI rules, schemas, composition root or architecture rules. Within each owner, D1/D2/D7 share service acquisition and cache, D4/D7 share HTTP origin/framing, and D3/D7 both depend on the HTTP prepared send boundary. Variant comparisons use private overlays of the same source without permanent product feature switches.
- **Planning hooks.** Keep the frozen base candidate identifiable before testing conditional variants. Align independent peer instrumentation and workload before building comparison artifacts. The distinguishing integration seams are the service selection/rejection/refresh race, pre-write HTTP retry and wire Host, and the immediate gRPC status hook versus later decoded outcome.

## Assumptions and reopen triggers

- **Benchmark scope.** A Linux CPU-optimized Droplet and loopback TLS peers can exercise the current public client paths with synthetic data. Reopen with Intake if obtaining valid comparison evidence requires additional cost-bearing resources or broader authority.
- **Pool workload.** The accepted workload uses a fixed URI spelling per target. Reopen on demonstrated recurrent alias use and compatible connection evidence as defined in D7.
