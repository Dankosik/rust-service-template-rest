probe); B uses PostgreSQL18 unique arbitration and current Tx (reject a generic
inbox library that cannot own business meaning); C uses native read/delete plus
the current Go wire helper (reject a custom delivery engine); D uses native
NATS snapshots/pg_dump/Docker (reject simulated restores). Parity belongs to the
existing Go wire, Tx and process gates plus actual fixture observations. An
upgrade requires a concrete provider gap; none is selected here.

No planned ownership change to `infra-postgres`, `infra-jobs`, `domain-events`
or service bootstrap is needed. T1 ownership review found the missing shared-pool
edge; T2 selects the exact worker composition extension above. Its factory is
the smallest present responsibility: deleting it requires either a second pool
or a replacement worker composition. Executor-local helper/test splits
stay adjacent to the named owner and preserve the same visibility/dependencies;
they are not new responsibilities or a preceding test-design phase.

Deletion self-check: removing either example loses an accepted executable
adoption/operator path; removing the shared effect module duplicates the very
logic being demonstrated; removing the fixture loses real backup/R3/TLS
observations. Everything else extends an existing owner. No broad refactor,
trait seam or future optional engine is justified.
