# Authentication system and integration design

Status: ready. Inputs: [reviewed Specification](../spec.md), [Definition transition](../definition-transition.md), [research](../research/synthesis.md). Original base `4edd184`; narrow cache reopen uses production commit `a896e21` plus the current disjoint mechanical cleanup. This design adds no implementation claim.

## Drivers and selected mechanism

The selected mechanism retains jsonwebtoken 11.1.0, reqwest 0.13.5, serde, Tokio watch, utoipa-axum 0.2.0 and axum 0.8.9. The service owns final contract assembly; infra-http owns contract enforcement; infra-bearerauthn owns provider trust, verification and refresh; config owns operator input shape; bootstrap owns preparation and process lifetime. No external dependency upgrade, new crate, database schema, live IdP, or readiness probe is added.

| Decision | Strongest alternative | Decisive constraint and accepted cost | Reopen condition |

A small registration carrier is necessary; axum still owns matching, dispatch and fallbacks. | A pinned supported library API exposes actual explicit method registration, or Specification changes this distinction. |

### Route construction and final enforcement

A private `ContractRouter<S>` representation in infra-http combines the existing OpenApiRouter with an actual-registration map keyed by normalized route template and explicit HTTP method. It is an inbound contract surface, not an auth-provider type. The service merges only these carriers before finalization. No `DerefMut`, opaque Router/OpenApiRouter import, unrestricted `route_service`/`nest_service`, or method-router mutation is exposed. Those routes could bypass provenance; a future need reopens this boundary rather than silently admitting them.

A small `infra_http::routes!` registration macro delegates annotation/schema extraction to existing `utoipa_axum::routes!` once per supplied handler. The public typed constructor receives that handler and the annotation tuple, discards the tuple's opaque MethodRouter, and constructs actual axum method registrations from the declared methods and that handler. It records exactly the methods it constructs. This is not a second annotation parser or a new routing implementation. The macro repeats the handler internally so authors write it once. It accepts multiple handlers and merges their registrations; several methods may share a path. A deliberately mismatched tuple cannot smuggle an extra HEAD endpoint: its opaque router is never served. Incorrectly describing the supplied business handler remains an ordinary source-contract defect, as with current utoipa, not authority from caller input.

For an explicitly registered but undocumented handler, the same carrier has a constructor taking the actual method, path and handler, constructing the axum endpoint and recording its method with no operation metadata. It is useful for detecting accidental contract omission and for the negative boundary proof. It cannot supply an opaque MethodRouter. RegisteredRoutes permits method-preserving `route_layer` operations for idempotency; it never gives back mutable endpoints. Carrier merge preserves both document and provenance. Current feature composition only needs merge, not nest; do not introduce unsupported nesting machinery. Parameter templates use the same representation passed to axum and utoipa.

Finalization consumes the fully assembled carrier and its exact OpenAPI value, builds an immutable policy table, validates security/exposure metadata, checks protected operations against disabled auth, and applies **one Router::route_layer** around all registered endpoints. Only after this step does bootstrap receive the router to supply state and harden. The document generator consumes the same assembled document without preparing providers; no generation-time network call occurs. An empty route tree skips axum's empty route_layer panic. Do not expose a second runtime split that omits finalization.

At request time the final layer reads MatchedPath and request method. For HEAD, it uses HEAD if the actual-registration map contains explicit HEAD; otherwise it uses GET only if actual GET exists. This preserves native implicit HEAD (including the original request method and body stripping). It then looks up that effective method in the final policy document: missing operation is sanitized 500 and the endpoint is not invoked. Explicit undocumented HEAD therefore gets 500 even alongside documented GET; implicit HEAD inherits GET. A path with no registration and a method with no endpoint never enter route_layer, preserving native 404/405. The hardened chain still wraps all fallbacks.

Global bearer is inherited only when operation security is absent; explicit empty security is public. Exactly the supported bearer requirement without scopes is protected. Anonymous alternatives, unknown schemes/scopes and contradictory exposure fail finalization. Public endpoints ignore Authorization and do not invoke the verifier. The auth layer removes preexisting Principal/VerifiedPrincipal extensions before admission; a protected operation additionally requires RequestDeadline and enabled verifier. Missing evidence is sanitized 500. Success strips Authorization, inserts the sealed Principal, and then enters idempotency/handler extraction. The HTTP helper for a missing required scope returns 403 with the specified insufficient_scope challenge.

The idempotency Composer retains declaration agreement, store and key admission. It no longer owns Verifier or wraps `protect`; it accepts the method-preserving registration carrier and applies only its own layer. Existing x-idempotent agreement still refuses invalid declarations. Final auth is applied outside those layers. Bootstrap retains Verifier independently of the optional Composer, so removing idempotency cannot remove auth. A health-only jobs listener continues its public probe behavior through the supported public contract construction; it does not prepare an API auth provider.

### Configuration and shared boundary types

`AuthnConfig` becomes an internally tagged enum with None as the omitted section default and mode-specific, deny-unknown fields. Preserve current mode spellings and environment-only secret policy. JWT fields: issuer, audience, token_profile, algorithms. Introspection fields: issuer, audience, introspection_endpoint, introspection_client_id, introspection_client_secret, provider_concurrency (nonzero, default 32), cache_enabled (default false), cache_capacity (default 256, inclusive 1–1024), and cache_ttl (human duration, default 30s, inclusive 1s–5m). The three cache keys are introspection-only; range errors fail startup even when caching is disabled. These conservative defaults bound retained state and revocation delay, not a throughput claim. None accepts no provider fields. The audience input is one string or a nonempty string list, normalized without changing exact string values; algorithms are a closed config enum for the four accepted spellings, default RS256. Bootstrap performs explicit value conversion into adapter options; config never imports a provider crate and provider never imports config.

Config owns presence/type/nonblank/range validation. It intentionally stops duplicating provider URL syntax. The adapter exports validated `ProviderUrl` through lib.rs; its implementation stays with provider.rs. The constructor retains both the exact original spelling for issuer identity and the parsed url::Url for requests. It admits HTTPS, host and the accepted no-whitespace/control/userinfo/query/fragment grammar using url 2.x parsing. Bootstrap validates every configured URL through this constructor before any provider I/O and annotates safe failure with the dotted config key/mode. Discovery invokes the identical constructor. No unchecked public constructor or mutable URL escape is exported. This preserves fail-fast startup, although a bare config deserialization by itself no longer certifies provider URL syntax. Config diagnostics remain structural; provider preparation owns transport admission.

Public adapter inputs remain options records, with issuer/endpoints as ProviderUrl, accepted audiences as exact owned strings, JWT token profile and closed algorithm enum, and introspection SecretString/client id/nonzero concurrency plus optional IntrospectionCacheOptions (capacity and max lifetime). Bootstrap maps disabled configuration to None; enabled options carry the selected bounds. The adapter validates these bounds for direct callers before creating state; it reads no environment. These records do no ambient environment access. The config enum uses its own input types and bootstrap converts explicitly; this small mapping is representation conversion, not duplicated validation or URL policy. Principal keeps a private constructor and fields; adds `scopes()` as an immutable normalized set view and `expires_at()` in unsigned epoch seconds. HTTP VerifiedPrincipal delegates those accessors and remains unconstructible by handlers.

### JWT preparation, key eligibility and verification

Preparation receives validated issuer/options, one client and the process tracker/token. Under the 6-second overall startup cap, discovery and JWKS each receive at most their 3-second attempt cap and remaining startup budget. Discovery's typed issuer must equal the original configured issuer exactly before its jwks_uri is validated or fetched. Only then may the usable initial key snapshot admit startup. Errors carry a closed phase/reason and safe bounded configured context; bodies, raw keys, tokens and raw reqwest/serde errors never become log fields.

JWKS top-level parsing requires an object with an array. Use a typed envelope holding individual serde_json Values (bounded by the existing 1 MiB body), then deserialize entries independently into the library Jwk. This limited per-entry value is for isolation, not a generic claims visitor. Unsupported or malformed entries are skipped with closed reasons. Admit only accepted key families/curves, signing-compatible use/key_ops, and exactly one configured algorithm binding. Omitted alg is admitted only if the family has one compatible configured algorithm. Before building DecodingKey with from_jwk, admit decoded public material through the bounded gate below. Canonical public-material identity uses those same admitted decoded public components and family/curve, ignoring kid, use and alg; RSA integer components normalize equivalent leading-zero encodings for comparison and the normalized JWK passed to from_jwk. No new hashing dependency is needed: equality of the small canonical component record suffices. Across the whole candidate set, conflicting algorithm assignments for identical material remove all those assignments. If multiple admitted entries remain eligible, selection is ambiguous as specified; do not introduce deduplication as a new acceptance rule.

The material gate is explicit because pinned from_jwk only decodes/stores components; it does not establish a usable key. Missing/invalid base64url/empty required components skip the entry. Normalize RSA n/e to positive unsigned big-endian bytes, rejecting zero values; retain the existing 2048–8192-bit modulus range used by the selected RS256/PS256 backend. Call already-resolved aws-lc-rs 1.18.1 `RsaPublicKeyComponents::to_parsed_public_key` with the matching RSA verification parameters. EC P-256 requires x/y of exactly 32 bytes; form its standard uncompressed point and call `signature::ParsedPublicKey::new` with `ECDSA_P256_SHA256_FIXED`, which validates the point/curve through the backend. Ed25519 requires its 32-byte x and the same import API with ED25519. Import rejection skips the entry. This uses backend-supported format/material checks, not a claim to prove private-key possession or every mathematical property; signature correctness stays with jsonwebtoken. The RSA import defers algorithm size limits, so the explicit existing modulus bound remains necessary. Only entries passing this gate, from_jwk and algorithm-conflict filtering can populate a candidate snapshot; zero survivors fails preparation/refresh and cannot overwrite last-good keys.

Declare one direct infra-bearerauthn dependency edge to the **already resolved** aws-lc-rs 1.18.1, via one workspace declaration with default features disabled and only the existing selected backend feature set. No version upgrade, second crypto implementation, new package, parser or extra unsafe code is added. This edge exists only in the JWT profile and is removed in introspection-only/no-auth projections. The public-import admission result may be discarded after checking; do not build a parallel signature verifier or cache. The alternative nonempty/length-only check cannot reject a correctly sized invalid P-256 point; a custom point/RSA arithmetic check is unnecessary. Reopen this mechanism if the resolved backend/import APIs or supported key families change.

A token is bounded before header decode. decode_header yields only local algorithm/kid/profile-header evidence, never a destination. Unsupported critical extensions reject. Where the library header representation omits crit, use a small typed header view over the already bounded JOSE segment solely for crit; no custom visitor or claims preprocessing. The token's alg must belong to configuration and match a key's prebound algorithm. Zero candidates may request bounded refresh; multiple candidates reject without refresh. No kid needs exactly one eligible candidate. Bind Validation to that one algorithm, exact issuer, configured audience set, required iss/aud/exp, leeway 30 and validate_nbf=true; then verified decode into typed claims. Explicitly select the aws-lc CryptoProvider before crypto use rather than invoking dual-feature auto-selection, and retain the manifest's single provider feature discipline.

Typed serde fields close issuer/audience/integer shapes and reject duplicate consumed fields. JWT omitted nbf is allowed; present nbf:null rejects through the library, as the reviewed Definition correction requires. Unknown extensions remain ignored. Small shared application normalization owns coherent identity aliases, resource-server subject-or-client policy, scopes and Principal creation. RFC9068 adds its required typ/sub/client_id/jti/iat and future-iat rule after verified decode; generic tokens do not acquire those requirements. Signature/registered-claim failures produce fixed 401 and bounded internal reason. Optional scope/scp null remains absent; if both are present their normalized sets must match. Scope tokens use the RFC grammar, exact case and no privilege union. exp stored in Principal is the verified claim, never skew-extended.

### Introspection and trusted transport

One reusable reqwest client uses supported HTTPS-only, default TLS certificate/hostname validation, no redirects, no ambient proxy and explicit retry::never. Retain normal pooling and protocol negotiation. Delete auth's provider/dns.rs and dependency on infra-egress-dns; Stage 10.2 outbound still owns that crate and its connection-address tests. Fixture transport keeps the existing local TLS root/host override only in test support, never runtime configuration.

After bearer-envelope and request-reserve admission, a disabled cache or eligible cache miss takes an immediate owned semaphore permit or gets 503; no waiting queue. A valid enabled-cache hit avoids both the permit and provider exchange. One RFC7662 POST on each admitted miss uses component-encoded client_secret_basic credentials only on the configured endpoint. No retry is introduced. Bound streaming body consumption, regardless of Content-Length. No auto-decompression feature is added; the same 1 MiB actual collected-byte bound applies. The 3-second provider attempt deadline and the request deadline minus 100ms reserve are separately identified; whichever bound actually ends the exchange determines 503 provider failure or 504 request timeout. If the request reserve is already exhausted, return 504 immediately. Drop cancels the request-owned exchange and releases its permit; there is no sleep/pending path to force an outer timeout.

The response is parsed once into a typed active envelope and, only for active=true, typed consumed claims. Keep raw claim evidence inside that parse representation until active is known so active=false ignores other claim meanings. Malformed JSON/envelope or duplicate consumed fields remains malformed provider evidence. For active=true, wrong types (including nbf:null) and malformed scopes are 503; missing required claims, inactive/wrong/expired/not-yet-valid token evidence are 401. Required null is missing evidence only when that claim's optional representation treats it as absent; numeric present null is a type error. This boundary returns typed outcomes/closed reasons, not generic deserialization errors. No HTTP status or Problem type enters the adapter.

### Optional introspection cache

The existing IntrospectionVerifier owns an optional shared in-memory store, allocated only when cache_enabled is true. Its clones share that store with the exact immutable issuer, accepted audiences, endpoint, client id and secret used at preparation. A separately prepared verifier always starts empty, even for identical options. There is no global map, persisted state, hot reconfiguration, exported cache handle or cross-verifier reuse. Thus exact token bytes are the only per-entry key: trust-context isolation is enforced by ownership, without hashing or copying credentials into keys. New credentials/options require a new verifier and empty store.

Use std::collections::HashMap with its default randomized hasher behind an Arc<std::sync::Mutex<_>> in introspection.rs. A private key owns a secrecy::SecretString, compares/hashes exact token bytes and exposes only borrowed lookup internally; Debug is redacted. No token digest enters logs or metric labels. The value retains only a sealed Principal and the validated optional nbf evidence needed for temporal revalidation, plus fixed expiration instants. It retains no raw provider body or unknown claim. Cached value and state Debug remain redacted; Principal stays sealed and its public API does not gain nbf or a raw-claims accessor. Secret token keys are zeroized on drop through secrecy; identity retains its existing in-memory confidentiality and redacted diagnostics, without claiming zeroization of all Principal allocations.

The selected capacity is a hard entry-count admission bound, implemented under one synchronous critical section. Opportunistically remove expired entries before insertion; when still full, decline caching the new success and return its verified Principal normally. A live entry is not replaced by a concurrent miss completion, so that path cannot renew its deadline. No LRU queue or eviction scoring is needed. Use try_lock: contention or poisoning skips lookup/insertion and uses the ordinary provider path, never waits, panics, authorizes from unavailable state or adds an async queue. No lock crosses an await, provider operation or claims parse. Retained variable allocation per entry is additionally capped at 64 KiB, counting the token and owned Principal string buffers and scope-vector backing allocation with checked arithmetic; oversized evidence is successfully returned but not cached. The count bound therefore limits variable retained payload to 16 MiB at the default and 64 MiB at the maximum, plus bounded map/entry/allocator overhead. This is a data-structure bound, not an RSS or performance claim. Implementation may keep a small private sizing helper with the Principal owner to account for actual buffer capacities; no public generic memory-accounting API is introduced.

Successful active-response verification produces private verified introspection evidence in claims.rs. That owner retains exp/nbf and supplies the same temporal validator to miss and hit paths; issuer/audience/identity/scopes were already checked under this immutable verifier context. Compute cache retention only after successful verification, sampling a monotonic completion instant and current SystemTime with subsecond precision. Require wall time strictly before exp. Set the entry's fixed monotonic expiry to completion + min(cache_ttl, exp minus sampled wall time); arithmetic/clock conversion failure declines insertion. On every lookup require both monotonic now < fixed expiry and wall now < exp, with no exp leeway. This combination prevents backward wall-clock movement from extending retention and forward movement past exp from admitting a hit. At/past either boundary remove/ignore the entry and perform normal introspection; the unchanged uncached 30-second leeway may still accept evidence that cannot be cached.

Lookup only selects candidate cached evidence; it is not the cache-success decision. After extracting/cloning that evidence, sample monotonic and wall time afresh immediately before declaring a hit. This final synchronous decision checks request deadline minus the existing 100ms reserve, both strict cache eligibility boundaries (monotonic now < fixed expiry and wall now < exp), and the shared exp/nbf temporal policy using that sampled wall time, including nbf after a clock rollback. Crossing either cache boundary during lookup/cloning/scheduling discards the candidate and takes the ordinary miss path; it cannot be admitted through the temporal validator's leeway. A temporal failure retains its current 401 classification; inability to read wall time retains provider-unavailable classification. Perform no await or further substantial work between this final decision and returning the sealed Principal; this closes the authorization decision, not preemption after that decision. Request reserve is also checked before cache access and immediately before returning a newly verified success. A cache hit cannot bypass that check, bearer parsing, the HTTP policy layer or scope authorization. The provider attempt's three-second clock starts only for a miss; cache work does not restart or extend the absolute request budget. No new timeout/Problem class is added.

Inactive, malformed, missing-claim, invalid, provider-error and timeout results never populate the store. Simultaneous misses may perform separate bounded exchanges under the existing semaphore; no singleflight or pending map is introduced. Expired entries are always misses, including during provider failure, with no fallback to stale evidence. A still-valid positive hit can hide provider failure or revocation until its fixed expiry; that is the deliberate operator-enabled behavior and must be documented. Disabling the feature and recreating the verifier discards all cache state. Dropping the last verifier releases the store; no timer, refresh task, readiness probe or shutdown stage is added. Expired allocations may remain until opportunistic cleanup or verifier drop, but can never be used and cannot exceed the storage bounds.

### Refresh state and lifetime

Initial usable keys seed `watch::Sender<Arc<KeySet>>`. Known-key verification clones the latest snapshot under a short watch borrow, releases it, and performs no async control-mutex wait. A separate small control state owns generation, in-flight reservation, last-started monotonic instant and last outcome; retain the existing Notify and completion-watch pattern. The control lock protects only these in-memory transitions and is never held across I/O, decode or waiter sleep.

Unknown-key callers first check their own deadline minus reserve. An active generation is joined; otherwise cooldown determines the prior success/failure result, or a new generation is reserved and the existing worker notified. A reservation carries generation identity, not the request's deadline. The worker owns its independent 3-second cap starting when the fetch begins. Periodic ticks (15 minutes, missed-tick Delay behavior) and unknown-key wakeups share this one reservation/single worker. Last-started and a 30-second cooldown bound unknown-key amplification; initial preparation counts as successful refresh for that cooldown. No per-kid map is accumulated. A waiter subscribes before testing completion, then awaits its generation within its own reserved deadline; lost wakeups cannot strand it. Abandoning one waiter never cancels the worker or another waiter.

Completion publishes a replacement snapshot only for a usable set and the active generation, before publishing that generation's success. Failure retains prior keys, records a closed failure reason and warns. Waiters re-read the latest snapshot and classify a still-missing key as 401 after success/success-cooldown or 503 after failure/failure-cooldown. Their own deadline takes precedence at exhaustion and yields 504 even if another waiter subsequently succeeds. Cached known eligible keys remain usable during failures and still undergo claims expiry validation. Ambiguity is always 401. Snapshot+completion sequencing is one worker-owned publication, not independent writers.

Bootstrap spawns only the one refresh loop through TaskTracker using a child of the process token. Cancellation prevents new refresh admission, cancels active provider work, publishes/terminates waiter state as unavailable unless their deadline already expired, and completes the tracked loop. Existing shutdown cancels, closes and joins the tracker under its background budget; startup refusal follows the same cleanup. Reqwest internal pool/connection tasks follow client-drop/runtime ownership; no undocumented direct join promise is made. No provider health probe is added: preparation gates initial JWT trust and runtime outage affects current authentication requests as specified.

## Material flow and finality summary

| Trigger / owner crossing | Representation and final effect | Failure / restoration owner |
| --- | --- | --- |
| Operator input -> config -> bootstrap -> adapter | Mode-specific raw config becomes validated options before I/O; none stays inert. | Config structural error or safe preparation error; operator corrects input and restarts. |
| Handler annotations + constructor -> service assembly -> HTTP finalizer | One document and exact actual-method map become immutable policy around every registered endpoint. | Unsupported security fails startup; runtime absent operation/identity/deadline fails 500; no handler effect occurs. |
| Caller -> auth -> idempotency/handler | Bounded bearer becomes sealed Principal, header removed before admission/extraction. | Fixed 400/401/431/503/504; scope denial 403; no identity is manufactured. |
| Issuer discovery -> JWKS -> crypto | Exact issuer authority selects the only dynamic endpoint; usable algorithm-bound keys publish together. | Initial failure refuses startup; refresh failure retains usable snapshot. |
| Unknown key / periodic tick -> tracked worker -> independent waiters | One generation; immutable snapshot publication precedes completion visibility. | Provider cap 503, waiter reserve 504, cancel joins; later valid refresh restores trust. |
| Opaque token -> introspection-owned cache or bounded POST -> verified evidence -> Principal | Default-off exact-token lookup is isolated by immutable verifier context. Hits recheck time/deadline; misses use one POST per permit. Only successful evidence enters bounded fixed-expiry storage. | Expired/full/contended cache uses normal verification; invalid token 401, malformed/unavailable provider 503, request budget 504. No negative storage or stale fallback. |
| Process stop -> worker/client lifetime | Cancellation and existing tracker join complete owned auth work. | Existing shutdown budgets own exhaustion; no auth-specific detached tasks. |

## Proof, cleanup and reopens

Implementation selects concrete tests from the Specification's material cases. Proof lives beside each owner, with service composition/process proof for full bootstrap and auth without idempotency. Reuse existing TLS fixtures and idempotency mounted tests; no new live IdP or database environment is needed to prove these authentication changes. Any claim about actual database semantics still follows its existing owner. Existing Stage 10.2 DNS tests remain. Final delivery owns one assembled build/test/gate run and independent authorization/lifecycle review; profile projections factor structural checks from expensive runtime builds.

Remove protect/ProtectError and the custom signature-only/visitor path, auth DNS implementation/dependency/tests, deadline sleep/pending workarounds, duplicated URL grammar and stale constructor call sites. Update marker ownership for whole JWT/introspection files; none/JWT-only/introspection-only outputs must retain only their selected engine and dependencies. Public contract composition remains available in generated no-auth profiles; a no-auth finalizer refuses effectively protected operations and handles public probes. Generated OpenAPI comes only from the new assembled annotations. Update architecture, authentication, config, authoring, initializer and Stage10.1 decisions in the implementation delivery; Stage10.2 policy is unchanged.

Reopen System Design for any bypass of the actual-method carrier or changed lifecycle/owner; Specification for caller behavior changes; Research for an unsupported resolved-library claim. Function bodies, local helper names, concrete test cases and test commands remain Implementation work. Exact exported responsibilities and file containment are in [ownership.md](ownership.md). Cache proof obligations are default-off provider calls; enabled valid hit; token/context isolation; non-sliding TTL and strict exp boundary; clock/deadline revalidation; capacity/contention/oversized-evidence bypass; no negative/error/stale reuse; and retained-profile closure. Cases, fixtures and commands remain executor-owned, using existing local TLS fixtures and controlled clocks rather than a live IdP.
