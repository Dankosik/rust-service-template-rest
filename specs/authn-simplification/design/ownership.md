# Authentication ownership map

Status: ready. [System design](system.md) owns mechanism; [Specification](../spec.md) owns behavior. This is Ownership Map V1. Exact symbol spelling may improve during implementation without changing these responsibilities or dependency directions; exported semantic contracts below are fixed.

## Exported contracts and independent ownership

- Config exports `AuthnConfig` tagged variants and its input audience/algorithm/profile types. None defaults at omitted section; variant fields/deny-unknown behavior are as System Design. Config transfers primitive URL strings, never a provider type. Bootstrap alone converts config values to adapter options and safe config-context preparation errors.
- Adapter exports `ProviderUrl::parse(&str)` with read-only exact-text/request-URL access, `JwtOptions` and `IntrospectionOptions` with validated ProviderUrl fields, audiences, profile/algorithm values or client secret/concurrency, preparation functions and Verifier. Parsing errors contain closed reasons, no rejected raw input. JWT preparation returns the prepared verifier and refresh future/lifecycle handle using the current bootstrap-owned spawn pattern; it does not spawn untracked work. Introspection preparation does not perform a provider request.
- Verifier's `verify(&BearerToken, absolute RequestDeadline instant)` returns sealed Principal or Failure. Failure retains Missing, Malformed, Oversize, Invalid and Unavailable classes and adds explicit Timeout; internal closed reason enums drive adapter diagnostics without adding provider details to HTTP failures. `PreparationError` is a distinct public safe error carrying phase/reason/context for startup; no raw error sources or response bodies are exposed through Display/Debug. The HTTP owner maps these classes to Problems and challenges.
- Principal access is issuer/subject/client_id/scopes/expires_at; no public constructor, unverified claim map or raw token accessor. Bearer parser receives the effective token bound from HTTP (`min(32 KiB, max_header_bytes)`) and enforces it before allocation/decode. Retain only the transport-private token borrowing needed for verify.
- Infra-http exports `ContractRouter<S>`, a method-preserving `RegisteredRoutes<S>` carrier and its small `routes!` convenience macro. Constructor ownership proves actual endpoints as described in System Design; it never trusts opaque tuple endpoints. It supports documented registration, explicit method+handler registration without document metadata, component-document merge, carrier merge, read-only document access, document-only consumption and one consuming finalizer. Private inner axum/utoipa values are not mutably exposed. Method-preserving layer application is the idempotency integration seam. No new trait or code-generation package is required.
- Finalizer receives the prepared Verifier and token bound when auth is retained, compiles policy from its final document plus actual-method map, refuses invalid startup configuration and returns the served Router with one auth layer. The no-auth generated form retains public contract construction/finalization but has no provider dependency and refuses protected policy. The jobs public-probe listener uses the public-only finalization path without auth provider preparation. The only runtime router extraction is finalization; document rendering has a distinct non-serving path.
- Idempotency `Composer::new` takes Store only; inert construction remains no-I/O. Its route method consumes/returns RegisteredRoutes and layers key handling only. `agree` still uses the exact assembled document and retains idempotency declaration/store lifecycle authority. It never exports a mutable inner MethodRouter. Authentication remains outside its admission; its VerifiedPrincipal consumption is unchanged.

These surfaces permit config, verification/transport, and HTTP/composition work to proceed against explicit contracts; Planning decides executable units and ordering. Do not divide one shared lib.rs or composition root among concurrent writers. Template/docs work consumes the final exported names and closure receipts; it may prepare documentation independently but cannot invent another API.

## Deletion test and compatibility

Deleting the contract carrier loses the only reliable distinction between an implicit GET fallback and an explicitly registered undocumented HEAD: pinned axum's method fields are private. Deleting its thin macro is behaviorally possible but repeats every author handler argument; the macro delegates all parsing/generation to the installed utoipa macro and contains no new grammar. Deleting the ProviderUrl newtype loses the one canonical grammar and validated endpoint handoff; creating a separate URL crate adds no responsibility, so it is rejected. Splitting config and adapter inputs preserves dependency direction; no shared config/runtime enum crate is needed. Existing claims.rs and refresh.rs keep real distinct parsing-policy and lifecycle owners; no generic utilities or new trait exists only for tests.

Source compatibility changes are deliberate in this template: authors import the new routes macro/carrier and remove protect; idempotency constructors stop taking Verifier. Config None rejects previously dormant fields. There is no deployed consumer or compatibility shim. Generated profiles must remove disabled engine files/dependencies, preserve complete public composition and compile the updated constructors. One final independent Technical Design review consumes the three ownership-panel lenses; Planning begins only after their common fixed candidate passes.
