## Implementation and coverage choice

The private `StreamingBase64` implements `SerializeAs<T>` for `AsRef<[u8]>`,
calling `collect_str` with `Base64Display` and `STANDARD`. Split annotations
keep the existing `Base64` decoder for all three fields. Derived field order,
version, owned-body transfer, generic preparation, and receipt/duplicate
control flow are preserved. No new dependency, public API or retained buffer.

Extended the existing public `Incoming` JSON-byte fixture, its primary
compatibility owner, with empty versus absent Content-Type, the `+` alphabet
character, a padded binary message ID, and large bodies with both padding
remainders. Independent literal Base64 expectations protect against alphabet,
padding and optional-field regressions, including after multiple display
chunks; they are not generated by the adapter or an encoder under test.
The prior fixture covered large complete triples and only absent/nonempty
Content-Type. No production test seam or duplicate lower-layer fixture was
added. Existing jobs tests continue to own generic preparation errors/order;
existing real-database webhook tests own admission, replay and commit outcomes.
