# Temporal decisions

<!-- template:begin temporal:docs-temporal-decisions -->
`crates/infra-temporal`, `crates/temporal-worker`, `crates/config`, and `Cargo.toml`
own the client/worker API, shutdown budgets, metric series, and exact SDK pins.
This record keeps only rejected alternatives, upstream SDK/wire constraints, and
reopen conditions.

| Choice / Rejected alternative | Decisive non-code reason | Reopen condition |
| --- | --- | --- |
| Single `crates/infra-temporal` crate (`role: "health-provider"`) with `worker` feature split (`temporalio-client` + `temporalio-common` default; `temporalio-sdk` + `temporalio-sdk-core` behind `worker`) over unconditional SDK linkage or two crates | Keeps `/service` free of `temporalio-sdk-core`, `sysinfo`, and `mockall` in `-p service` builds without doubling crate boilerplate and policy rules for one adapter. `temporalio-common` and `temporalio-sdk-core` omit `tls-aws-lc` (enabled only on `temporalio-client`) because enabling it there pulls `opentelemetry 0.32` into `Cargo.lock`. | A second non-worker binary consumes `temporalio-sdk-core`, or feature crates need compile-time separation under `--workspace` builds. |
| Dedicated `/temporal-worker` binary (`crates/temporal-worker`) over extending `crates/jobs-worker` | Co-hosting mixes Temporal sticky-cache memory and long activity shutdown budgets (`90s`/`60s` via `TemporalWorkerHttpInput = HttpFields<Skip, 90, 60>`) with `jobs-worker`'s `45s`/`25s` budgets, OLTP PostgreSQL pools, and NATS/webhook secret boundaries, and would force `jobs-worker` onto standalone `--temporal sdk` services. | A third worker binary shares identical listener and shutdown stages, or deployment constraints forbid a separate worker binary. |
| Transport-only `/temporal-worker` with `Registration` lifecycle hooks (`add_readiness_probe`, `register_close_hook`, `spawn`, `shutdown`) over template-managed DB/cache/S3 wiring inside `temporal-worker` | Keeps worker deployments lean with zero unused drivers or secret surfaces while letting derived services open and close only the dependencies their activities call. | Most derived services share one standard PostgreSQL-backed activity setup needing built-in pool wiring. |
| Dedicated OS thread per task queue (`Handle::block_on(worker.run_until(...))`) + `ForceShutdownActivityInterceptor` returning `ActivityError::WillCompleteAsync` on forced drain (`exit 3`) over shared `LocalSet` multiplexing or returning `ActivityError::Cancelled` | `Worker::run_until` returns `!Send` (`LocalSet` + `RefCell`); isolating each queue off Tokio worker threads prevents heavy history replays from starving `/health/live`, `/health/ready`, `/metrics`, or signal handling. Returning `ActivityError::WillCompleteAsync` releases Core permits locally with zero RPC so Temporal Server retries preempted activities instead of recording terminal cancellation. | Upstream `temporalio-sdk` makes `Worker::run_until` `Send` or ships a native worker-preemption API. |
| Direct `CoreMeter` -> workspace `metrics 0.24` bridge (`temporal_` prefix, `.metric_prefix(String::new())`, `TaskQueueLabelStrategy::UseNormal`) + custom OTel `0.33` `_tracer-data` interceptors (`!is_replaying()`) + `temporal_sdk_log_cap` over SDK `opentelemetry`/`otel`/`prometheus` features | SDK telemetry features pull `opentelemetry 0.32` (breaking workspace `0.33` global trace propagation) or spawn a competing `prometheus 0.14` HTTP listener. Suppressing replay spans avoids duplicate exports on history replay; `UseNormal` avoids sticky queue UUID cardinality; capping `temporalio_*` and `temporal_client` at `INFO` keeps SDK debug chatter out unless explicitly named in `log.level`. | `temporalio-sdk` upgrades to the workspace `opentelemetry` minor and integrates with an injected Prometheus recorder. |
| `FiniteBoundedJsonConverter` on `PayloadConverter::composite([UseWrappers, Serde])` + optional `PayloadCodec` under `=1.2.0` pins over bare `PayloadConverter::Serde` or raw `serde_json` | Enforces `json-payload` finite-float validation and `temporal.max_payload_bytes` before RPC dispatch while preserving `binary/null` parity. In `temporalio-common-wasm =1.2.0`, `MemoValue` does not override `as_serde()`, so bare `PayloadConverter::Serde` fails `StartRequest::memo` with `WrongEncoding`; `PayloadConverter::composite` is `#[doc(hidden)]`, mitigated by exact `=1.2.0` pins and unit tests. | Upgrading `temporalio-common` past `=1.2.0` exposes a public composite converter constructor or `MemoValue::as_serde`, or a feature requires `ProstSerializable` protobuf Temporal payloads alongside JSON. |
| Idiomatic upstream `#[workflow]` / `#[activities]` authoring paired with bounded `TemporalClient` / `WorkflowHandle<W>` and `infra-http::temporal` Problem mapping over a custom workflow macro/trait | Preserves Temporal's native replay/select/signal/update authoring while enforcing `OperationContext` deadlines, explicit `StartIdPolicy`/`MutationDedupe`/`UpdateId`, zero-retry `signal_with_start`/`Unkeyed`/`terminate`, `OutcomeUnknown` honesty, and sanitized RFC 9457 Problem mapping without pulling `service-failure` into `infra-temporal`. | Upstream `temporalio-client` removes `Unspecified` defaults and exposes caller-budgeted `OutcomeUnknown` outcomes directly. |
| Scoped `deny.toml` waivers + `vendored-protox` + MIT `.clarify` entries in `build/docker/rust-notices.toml` + offline `ReplaySuite` and digest-pinned Compose `temporalio/temporal` over `temporalio-sdk/testing` or host `protoc` | `vendored-protox` keeps builds pure Rust; `temporalio-sdk/testing` pulls `ephemeral-server` (`zip`/`bzip2`/`zstd`, `reqwest`, and runtime binary downloads) into `deny.toml`'s `all-features = true` graph; `deny.toml` scopes `RUSTSEC-2026-0543` `chrono` waivers strictly to `temporalio-common-wasm`, `prost-wkt`, and `prost-wkt-types` while keeping `chrono` banned in service crates. | Transitive Temporal crates drop `chrono` or upstream splits `ActivityEnvironment` from `ephemeral-server`. |
| Live `api_key_file` rotation + opt-in `mtls_rotation = "dynamic"` (refused with `dns_load_balancing = true` or `http_proxy_url`), `http://`-only `http_proxy_url` without userinfo, and `tls_active == (scheme == "https")` over defaulting mTLS to `"dynamic"` or allowing `https://` proxy URLs | Upstream `dynamic-tls` conflicts with `dns_load_balancing` and `http_connect_proxy` and ignores `connect_timeout` (so connect is wrapped in `tokio::time::timeout`); `HttpConnectProxyOptions` dials plaintext `TcpStream` only, so admitting `https://` proxy URLs would silently downgrade TLS; rejecting TLS/mTLS options on `http://` and always installing `Some(TlsOptions)` on `https://` fails closed against misconfiguration. | Upstream `temporalio-client` removes the `dynamic-tls` vs DNS-LB exclusion, honors `connect_timeout`, and supports TLS proxy tunnels. |
