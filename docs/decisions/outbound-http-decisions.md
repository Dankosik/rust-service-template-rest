# Outbound HTTP decisions

This page records the durable technical decisions behind the optional bounded outbound profile. `crates/infra-outbound-http` owns normal usage, limits, and compatibility.

## Selection and rejected alternatives

| Decision | Alternative and decisive evidence | Accepted cost and reopen condition |
| --- | --- | --- |
| Direct `hyper-util` + `hyper-rustls` HTTP/1 client with `aws-lc-rs`, platform verifier, system DNS (`GaiResolver`), and Happy Eyeballs ([vendored patch](../../vendor/hyper-util/PATCHES.md)) | `reqwest` (adds URL/header copies and layers for redirects, retries, proxies, and decompression that this client disables) and the removed `infra-egress-dns` resolver/public-address classifier (blocked private providers with valid TLS certificates). | Deployment network controls, provider configuration, and TLS form the trust boundary; untrusted caller destinations require a separate SSRF decision. System `getaddrinfo` is not guaranteed abortable on future drop, and Linux snapshots system roots at first construction. |
| One shared process-wide `rustls::ClientConfig` | Per-client root-store parsing (cost ~6 ms and ~85 KB per webhook endpoint client) and separate session caches. | Concurrent first callers may build duplicate configs transiently; a trust-store change on Linux requires a restart. |
| Strict `http::Uri` origin match, HTTP/1.1 normalization, and body-derived `Content-Length` | Re-parsing `Uri` -> `String` -> `Url`, or passing caller `Host` / `Transfer-Encoding` / mismatched `Content-Length` (connection-pool smuggling under RFC 9112 §6.3). | Non-canonical spellings of the same address are refused rather than normalized. |
| Single `OperationContext` deadline across connect, headers, and `http-body-util` `Limited` body read; `UrlTemplate` opt-in extension; adapter-owned `backon` retries and concurrency | Header-only deadlines, client-owned admission semaphores, or automatic `url.full` / trace-context injection (paths/queries in webhook URLs can carry provider secrets). | Each adapter owns provider concurrency (`infra-jobs` worker slots or OAuth semaphore), retry eligibility, and trace propagation (`Client::with_trace_context()`). |
| Per-attempt span and `metrics` recording without a per-client metric-handle cache, `Content-Length` presizing, or a 16 KiB hyper read buffer | Caching metric handles per client silently binds an attempt to the recorder active at first call (misrouting test recorders); `Content-Length` presizing lets an untrusted declaration reserve memory before bytes arrive; a 16 KiB hyper buffer regressed large-body throughput. | Span creation remains the dominant per-request cost, kept because the observability contract requires it. |

The default-off `test-support` feature exposes only a literal-loopback mock constructor; [the shared TLS fixture](../../test/fixtures/tls.rs) keeps `rcgen` dev-only and requires `package.metadata.cargo-shear.ignored` entries until `cargo-shear` follows `#[path]` sources outside target directories.

## Error, API, and transport-setting decisions

These close the open questions of the 2026-11-09 readability review.

- **Cancellation is `Error::Cancelled`, not `Timeout`.** `OperationContext` already tells a deadline from a cancellation, and the adapters did: OAuth2 mapped its own cancelled wait to `Unavailable` but a cancelled token exchange of this client to `Timeout`. A cancelled attempt is observed like a dropped one, `outbound_outcome="cancelled"` with no `error.type`, so a caller going away never counts as a provider failure. No shipped alert selected `error_type="timeout"`. This holds when cancellation is observed before the deadline. If the deadline has also expired by the time the stop is observed, `OperationContext` reports `Stopped::Deadline`, so the attempt is recorded as a timeout; the context does not retain which event happened first.
- **`BuildError` is `InvalidOrigin`, `InvalidLimits`, or `Tls`.** The origin is operator configuration and the limits are adapter constants, so the startup error names which one to fix. Webhook and OAuth2 keep their own stricter URL checks; those are their policy, not a copy of this one.
- **The re-exported `http` types stay as they are.** The set is what a caller needs to build a `Request<Bytes>` and read a `Response<Bytes>` without its own `http` dependency: `Request`, `Response`, `Method`, `StatusCode`, `Version`, `HeaderMap`, `header`, `Bytes`, and `Url`. A type is added when a public signature or that read path needs it.
- **A transport failure's class has explicit precedence**: `tls`, then `connect`, then `protocol`, the first found anywhere in the chain. A failed connect parsed no response, so `connect` outranks `protocol`; before, the deepest match won.
- **`QUERY` is a known method in both HTTP crates.** OpenTelemetry lists it among the `http.request.method` values (Development stability, from the HTTP QUERY draft); `infra-http` now labels it too instead of `_OTHER`, so client and server series agree. Reopen if the convention drops it.
- **The connect budget is half the operation budget**, so a stalled connect fails as `connect` while TLS, the request, and the response keep the other half; a whole-budget connect would report every unreachable provider as `timeout`.
- **Pooled connections idle out after 30 s, below hyper-util's 90 s default.** Common provider front ends close idle keep-alive connections after 60 s (AWS ALB) or 75 s (nginx); retiring the connection first avoids reusing one the provider is closing. Hyper-util retries only a request it never sent on such a connection, so a shorter idle time removes most of those races rather than relying on that retry.

## Reopen conditions

Reopen the design if the pinned hyper-util and hyper-rustls APIs cannot maintain the configured transport invariants, if a retained profile cannot consume the shared TLS source, or if observation cannot finalize exactly once across timeout and future drop. Reopen the definition if trusted-origin, TLS, compatibility, or observable behavior constraints cannot be satisfied. A hyper, hyper-util, hyper-rustls, rustls, http-body-util, rcgen, metrics, tracing, or OpenTelemetry-convention change requires rechecking the affected decision; it does not silently change this profile.
