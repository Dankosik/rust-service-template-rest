# Shared rules decisions

Recorded 2026-11-12. `crates/shared-rules` owns rules that several crates must
apply identically when they have no other common owner; its crate
documentation holds the membership test. This record keeps why the rules live
there, what was rejected, and when to revisit.

## Selection and cost

| Decision | Alternative and decisive evidence | Accepted cost and reopen condition |
| --- | --- | --- |
| One always-present crate with modules named after the authority behind each rule (`rfc6749`, `uri`, `otel_http`, `error_chain`, `jitter`) | Twelve copies of five rules lived in seven crates because optional profile crates cannot depend on each other or on `config`. Copies of one rule had already drifted: `config --secrets-dir` strips every trailing line break from a secret file, while the cache and PostgreSQL `password_file` readers strip one. Rejected: documented twins (each rule kept N copies and N tests); modules in `operation-context`, `infra-http`, `infra-telemetry` or `config` (new provider edges into the inbound HTTP stack, the OpenTelemetry SDK or the loader, and wider crate charters); one crate per topic (one or two functions each); one source file included by `#[path]` (no single owner for readers or tooling); a derived template profile per module (each touches five or six initializer files). rust-analyzer's `stdx` and Materialize's `mz_ore` keep such code in one crate with a one-sentence charter. | The crate grows by review against its membership test, not by a hard limit. Reopen as a thematic split when several modules change for one reason or the crate passes about ten modules. |
| No dependencies beyond `std`: the `shared-rules` role is `std_only` in `quality/architecture.json`, and `architecture-check` refuses every non-dev edge | A catch-all crate's main cost is the dependencies it attracts (Go blog "Package names"; matklad, "Fast Rust Builds"). `mz_ore` makes any external crate optional and feature-gated. | Rules that need a crate stay with their owners. Reopen when one does, starting with the RFC 7519 `NumericDate` twin in `infra-bearerauthn` and `infra-serviceauth` (`serde`): give that module a feature of its own name with an optional dependency rather than a required one. |
| The crate exists in every template projection; `infra-http` consumes `otel_http`, so its workspace entry is used in every graph. A module whose consumers all belong to one profile carries that profile's marker (`uri`, `outbound-auth`); other modules stay as inert pure code | cargo-shear 1.14 reports an unused `[workspace.dependencies]` path entry unless `keep-path-dependencies` is set. A derived profile per module would remove the inert code at the initializer cost above. A consumer whose only uses sit inside a profile marker marks its dependency line the same way (`config`). | A service without a module's profiles keeps a few dozen lines of unused `pub` functions; they raise no warning and need no dependency. Reopen if no always-present crate consumes the crate: then set `keep-path-dependencies` or gate the crate on its consumers. |
| `otel_http::request_method` takes `&str`; `infra-http` passes `Method::as_str()` | A `match` on `http::Method` constants would need the `http` crate. Measured on Apple silicon (release, fat LTO, 200 million calls): 1.0 ns per call for the constant match, 1.9 ns for the string match. `infra-http` labels a request two or three times. | About 3 ns per request. Reopen if a profile of the request path shows the label. |
| `.jscpd.json` thresholds stay at 100 tokens and 15 lines; no new duplication gate | jscpd 5.4.2 on `crates/` at 13a298be: 10 clones at 100/15, 267 at 50/5, 1263 at 30/3, with 2, 22 and 87 of them across crates outside tests. `--similarity=0.9` reported 25 cross-crate pairs, about 20 of them alike only in shape (`as_str` matches, redacted `Debug`). No mode found the scope-token or method-label copies, which spell one rule with different tokens or fit on one line. The copies existed because no owner did. | A new copy of an extracted rule is caught only in review. Reopen when one appears: add an ast-grep rule for the rule's canonical spelling with `ignores:` for the owner file. |

Pending with their owners: one secret-file rule for `config`, `infra-cache` and
`infra-postgres` once the line-break behavior is chosen, and the RFC 6750
Bearer grammar shared by `infra-bearerauthn` and `infra-serviceauth`.
